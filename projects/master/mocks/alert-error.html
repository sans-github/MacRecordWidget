Error — modal alert

Recording failures are reported by a critical NSAlert, not inside the panel. The row has no space for a message and no state to show one in. Camera problems are the opposite case: they are reported inside the preview and never raise an alert.

⚠️
Could Not Start Recording
The recording shortcut could not be launched. Make sure a Shortcut named “Start” (or “Stop”) exists in the Shortcuts app. Detail: NSWorkspace.open returned false
OK

Any other errorRecording Errorerror.localizedDescription

Two cases, and that is all of them. RecordingError has a single case; the second row is the fallback for anything thrown that is not a RecordingError. There is no Accessibility permission case — the app never asks for Accessibility, and RecordingError.accessibilityDenied has been deleted.

When it fires

  • Start fails: the “Start” Shortcut does not exist, or NSWorkspace.open refuses the shortcuts:// URL.
  • Stop fails: the same, for the “Stop” Shortcut.
  • Nothing else raises it. Camera permission, a missing camera and a failed capture session are all handled inside the preview.

Behaviour after an error

  • isRecording flips only after the Shortcut URL opens, so a failed Start leaves the toggle exactly where it was. There is no half-recording state to recover from.
  • The toggle also reverts visually, because it is bound to isRecording rather than to the click.
  • The alert is app-modal with one OK button. Dismissing it returns the user to the panel, which stayed open.
  • It appears over whatever is frontmost: a menu bar panel cannot host a sheet, so an alert is the only correct container here.
