The one open design decision, decided

The PRD constrains behaviour, not placement. Recommendation: a 22pt control strip below the preview, with the picker's own selected-value label doing the job of the passive camera-name indicator. No chrome over the video. The short reason: six of the eight states have no image to overlay, and text over a live feed cannot be made legible without a scrim across the part of the frame the user is trying to judge. Full reasoning and the rejected overlay, drawn, on the placement decision page.

Accessibility

No focus ring: the preview and its controls inherit .focusEffectDisabled() from the shipped row (AC-AX-4). Tab still reaches the picker and the checkbox in reading order and Space activates them; nothing is drawn. Reduce Motion removes the panel resize animation (AC-PNL-4) and replaces the waiting spinner with static text. Increase Contrast and greyscale are safe because no state is distinguished by hue — every state message carries its meaning in text, and this feature adds no colour-coded status anywhere. Dynamic Type now applies to the panel for the first time: the state messages are the only text in the product, and they wrap rather than truncate.

Menu bar and keyboard

Unchanged, and unchanged deliberately. The app remains a MenuBarExtra-only agent app with no application menu bar, no Settings scene and no registered shortcut, so this feature adds no menu item and no key equivalent. Both new controls are reachable by Tab within the panel and by VoiceOver. Adding a Settings window for two preferences would introduce the first window this app has ever had, which is out of proportion to a picker and a checkbox that are already permanently visible whenever they apply.

Not expressible in a mock

These PRD requirements are behavioural and cannot be verified from a static page. They are specified in the mapping tables so they are not lost: session lifecycle tied to the popover (AC-LC-1 to AC-LC-5), persistence of the device ID and the mirror flag (AC-PS-1 to AC-PS-4), the fallback rule that never overwrites the stored device ID (AC-CAM-4, AC-CAM-5), and the guarantee that no code path writes the preview stream anywhere (AC-PV-4). The engineering prerequisites P-1 to P-4 are outside design entirely.
