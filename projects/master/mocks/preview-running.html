The camera toggle is on. Two things happen: the 480×270pt preview appears below the row, and the camera picker appears in the row beside the toggle that summoned it. The panel grows downward; its width and its trailing edge do not move.

What the preview is

  • Display-only. It shows a live image and never writes a file. Nothing in the app captures video; recording is audio, through the “Start” Shortcut into Voice Memos.
  • The session starts when the toggle turns on and stops when the popover closes, so the camera activity light cycles with the panel. That is by design, not a leak.
  • Mirroring is on and there is no control for it. A left-right flipped self-view is what a user expects from a mirror; an unmirrored one reads as broken.
  • Turning the toggle off tears down the session and collapses the panel by the same 278pt it grew.

Camera picker

A small pop-up button, capped at 200pt so a long device name cannot push Quit out of the row. Its selected value doubles as the camera-name indicator: it names the device actually feeding the layer, which after a fallback is not necessarily the stored preference.

Selection persists in UserDefaults. If the selected camera disconnects, the preview falls back to another one without discarding the stored preference, so reconnecting the preferred device restores it. The picker follows the fallback, so it never names a device that is not live.

TransitionNot animated. The preview fades in with .transition(.opacity); the window frame itself changes in one flush.

Heights are derived from the layout constants rather than measured on hardware. Only the height figure is derived; the 504pt width, the 8pt margin and the un-animated resize are all fixed in code.

Why the width is frozen: a width change forces AppKit to reposition the panel as well as resize it, and the status-item-anchored position is painted before the correction lands, which reads as the panel jumping sideways. Holding the width constant means only the height ever moves.

Long content and edge cases

  • A camera whose aspect ratio is not 16:9 fills the 480×270pt frame and is cropped (videoGravity = .resizeAspectFill); it is never letterboxed and never stretched.
  • More cameras than fit on screen is a system menu concern — the pop-up scrolls; the row does not grow.
  • Every non-running condition replaces the image with a message in the same frame, so the panel height never depends on the camera state. See permission and hardware states.
