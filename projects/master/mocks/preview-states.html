Why restricted has no button

Denied and restricted look alike and are not alike. Denied is the user’s own choice and Privacy & Security reverses it, so that state gets an Open Settings button. Restricted comes from MDM or parental controls, and that pane cannot resolve it — a button there would send the user somewhere that cannot help. The copy says so instead.

Each state is distinct in the model, not collapsed into one “camera unavailable” case, because the recovery differs in each one and a single message could only describe one of them.

Recovery

  • Disconnect while running. The preview falls back to another available camera and keeps the stored preference. Reconnecting the preferred device restores it. If no camera remains, the area becomes noCamera.
  • Reconnect. Handled without user action; the picker updates to name whatever is live.
  • Permission granted after denial. The state is read when the session starts, so turning the camera toggle off and on picks up the new grant. macOS may also terminate the app when camera access changes, in which case the preview is running on the next launch.
  • Retry. Turning the camera toggle off and on tears down and rebuilds the session; that is the only retry affordance, and it is the same control the user already used to get here.

Presentation

Symbol at 22pt, copy at 12pt, both .secondary, centred over underPageBackgroundColor with 16pt of horizontal padding. Every message is a full sentence in plain language: no error codes, no state names, except in failed where the underlying reason is more useful than anything generic. VoiceOver reads the copy as written, so no separate accessibility string is needed.
