Approved design, not shippedThis page is the live camera preview as designed and approved on 4 September 2026. It was never built: implementation was deferred, so no shipping build of MacRecordWidget has a camera preview. For what the app actually does today, see the shipped mocks.

Preview — permission and hardware states

Six states in which no live image is available, plus the two recovery states that follow them. In every one of them the button row is untouched: Start and Stop keep their normal enabled and disabled logic based on recording state alone (AC-ST-7), the video toggle stays usable (AC-ST-8), and nothing is presented modally (AC-ST-9).

The one rule these states share

The message replaces the image, never the panel. The preview well keeps its exact 480×270pt footprint and fills with the window background instead of video, so the panel never changes height between states and the button row never moves under the pointer. A user who opened the panel to press Stop finds Stop where they left it, whatever the camera is doing.

  • The system permission sheet owns the interaction, so the panel offers no action of its own — a button here would compete with the sheet (AC-ST-1).
  • An indeterminate ProgressView, not a caution glyph. Nothing has gone wrong yet.
  • The picker and the mirror checkbox are disabled for the duration: there is no device list to choose from and no image to mirror.
  • Under Reduce Motion the spinner is replaced by static text; the copy alone carries the state.

Permission denied

Popover, 504×346pt
Camera access is off
MacRecordWidget needs camera access to show a preview. Recording still works.
Open Settings
No camera access
Mirror
  • One action, and it is the only one that resolves the state: it opens Privacy & Security → Camera directly, not the top of System Settings (AC-ST-2).
  • The second sentence is the important one. It tells the user, before they go anywhere, that the thing they opened the panel to do still works.
  • No red, no caution triangle. This is a setting that is off, not a failure. The icon is tertiary label colour like every other state icon on this page.
  • The picker is disabled because without authorisation the device list is not trustworthy; switching device would not produce an image.

Permission restrictedno action, deliberately

Popover, 504×346pt
Camera access is blocked by a system policy
This is set by whoever manages this Mac. Recording still works.
No camera access
Mirror
  • Deliberately no Open Settings button. Under a restriction the camera row in System Settings is disabled, so the button would open a page the user cannot act on — a dead end that reads as the app being broken (AC-ST-3).
  • The copy names who can change it instead of offering a control that cannot. That is the honest substitute for an action.
  • Same layout, same well, same disabled controls as the denied state. Only the icon, the copy and the missing button differ — which is exactly the difference in what the user can do.

No camera connected

No camera
Mirror
  • Self-clearing: a device-connected notification starts the session with no user action, so the copy promises exactly that (AC-ST-4).
  • No Retry button. There is nothing for it to retry that the system does not already tell the app.
  • The picker shows "No camera" and is disabled: an empty menu that opens onto nothing is worse than a disabled control that says why.

Mirror
  • Names the camera that was lost, so the user knows which cable to check (AC-ST-5). Present tense on the second line: the fallback is already happening.
  • This state is transient. It holds for about a second while the new session configures, then resolves to the recovery state below.
  • The picker stays enabled throughout (AC-CAM-7) — the user may want to pick a third camera rather than accept the fallback.
  • The persisted device ID is not rewritten by the fallback (AC-CAM-4). Plugging the BRIO back in restores it and the picker follows (AC-CAM-5).

The indicator is the whole point of this pair of frames: it now says FaceTime HD Camera, while Photo Booth may still be pointed somewhere else. The label states what is on screen and nothing more — it does not claim to describe what Photo Booth will record, because the app cannot know that.

Camera busyunverified — may be unreachable

Popover, 504×346pt
FaceTime HD Camera is in use by another app
Choose another camera below, or quit the other app.
FaceTime HD Camera
Mirror
  • Unverified. macOS generally lets several processes read one camera, so this state may never be reachable in practice. The PRD (AC-ST-6) keeps it in scope pending verification during implementation, so it is drawn and specified here.
  • The copy points at the one control that can resolve it, and the picker is enabled so the pointing is not empty (AC-CAM-7).
  • It names the busy device but not the app holding it — macOS does not reliably tell the app who that is, and guessing wrong is worse than not saying.
  • If verification shows the state is unreachable, delete the state; do not repurpose the copy for a different failure.
