The shipped panel

Shipped: what the app does today

One menu bar item, one 200pt panel, one row of four controls. This is the popover button layout release, and it is what a user gets if they build and run main right now.

Idle

Default state. Video off, Start available, Stop dimmed. Includes the hover, pressed, focus, disabled and in-flight matrix.

Video mode armed

Toggle on. Symbol swaps to video.fill so the state reads without colour. Photo Booth opens on the next Start. The panel itself does not change size and shows no preview.

Recording

Stop is the only enabled action. Menu bar icon turns green with a blinking amber dot, static under Reduce Motion.

Error alert

Failures surface as a critical NSAlert, not inside the panel. All three error cases listed.

Menu bar and keyboard

Shipped behaviour. The approved preview design changes none of it.

The app has no application menu bar. It is a MenuBarExtra-only agent app: there is no WindowGroup, no Settings scene, and no commands {} block, so no App, File, Edit, View, Window or Help menu exists and no keyboard shortcut is registered. Quit is reachable only through the power button in the panel, not ⌘Q.

Inside the panel, Tab moves focus across the four controls in reading order and Space activates the focused one; the focus ring is suppressed by .focusEffectDisabled(), so focus is not visible while tabbing. Both of these are deliberate consequences of the current design rather than specified behaviour, and both are open questions for the next design pass.
