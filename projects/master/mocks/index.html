MacRecordWidget — master mocks

The product baseline: what the app does in the current build, nothing else. Every page here describes shipped behaviour as of 4 September 2026.

Audio

The panel, idle — 504pt wide

What the app records

Audio only. Start fires a user-created Shortcut named “Start” which records into Voice Memos; Stop fires “Stop”. Nothing in the app captures video. The camera preview is display-only: it shows a live image in the panel and never writes a file.

Photo Booth is not launched, and the code that used to launch it is deleted. If a page anywhere still says video is captured, that page is wrong.

Control chrome

Every control in the row is .controlSize(.small) with a 13pt glyph centred in a 16pt frame, and carries a constant 1pt separatorColor outline. The outline is the reason for the rule: without it a button toggle only draws an edge when it is on, so an off toggle and an on toggle read as two different objects instead of one control in two states.

Menu bar and keyboard

The app has no application menu bar. It is a MenuBarExtra-only agent app: no WindowGroup, no Settings scene, no commands {} block, so no App, File, Edit, View, Window or Help menu exists and no keyboard shortcut is registered. Quit is reachable only through the power button in the panel, not ⌘Q.

Inside the panel, Tab moves focus in reading order and Space activates the focused control. .focusEffectDisabled() suppresses the focus ring, so focus is not visible while tabbing. Both the missing menu bar and the invisible focus ring are consequences of the current design rather than specified behaviour, and both remain open questions.
