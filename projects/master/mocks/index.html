MacRecordWidget — master mocks

The product baseline: what the app does in the current build, nothing else. Every page here describes shipped behaviour as of 5 September 2026.

The panel, idle, at the default medium scale — 480pt wide

What the app records

Audio only. The audio toggle fires a user-created Shortcut named “Start” which records into Voice Memos; turning it off fires “Stop”. Nothing in the app captures video. The camera preview is display-only: it shows a live image in the panel and never writes a file.

Photo Booth is not launched, and the code that used to launch it is deleted. If a page anywhere still says video is captured, that page is wrong.

The button row

One row, left to right. Order is fixed. The row contains no text of its own — the “Audio” label was removed. The only characters anywhere in it are the camera name inside the picker and the S, M and L letters, and both of those appear only while the camera is on.

Control chrome

Every control in the row carries a constant 1pt separatorColor outline at scale.cornerRadius. The outline is the reason for the rule: without it a button toggle only draws an edge when it is on, so an off toggle and an on toggle read as two different objects instead of one control in two states.

An on toggle fills with the accent colour, the same way in every case: the pin, the camera toggle and the selected size button are all accent-filled when active. The audio toggle is the single exception — it is tinted red, so recording is the only red thing on screen.

Menu bar and keyboard

The app has no application menu bar. It is a MenuBarExtra-only agent app: no WindowGroup, no Settings scene, no commands {} block, so no App, File, Edit, View, Window or Help menu exists and no keyboard shortcut is registered. Quit is reachable only through the power button in the panel, not ⌘Q.

Inside the panel, Tab moves focus in reading order and Space activates the focused control. .focusEffectDisabled() suppresses the focus ring, so focus is not visible while tabbing. Both the missing menu bar and the invisible focus ring are consequences of the current design rather than specified behaviour, and both remain open questions.

Reduce Motion removes the menu bar dot blink.

Recording state and colour. The audio toggle no longer changes shape between its two states: it is mic.fill whether idle or recording, and only the fill flips. That fill is a large luminance change rather than a hue change — a filled button against an unfilled one — so it survives greyscale and Increase Contrast, and it is the same distinction the camera toggle and the pin already rely on. The tooltip and the VoiceOver label both change with the state, and the menu bar icon separately turns green and gains a blinking amber dot. Recording state is therefore never carried by hue alone. It is now carried by fill alone within the panel, which is a narrower margin than the previous glyph swap gave; that trade is recorded on the recording page.

Dynamic Type applies only to the camera name, the S/M/L letters and the preview message copy. The row contains no other text.
